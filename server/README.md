# Сайт і адмінка — запуск та обслуговування

Сервер написаний на чистому Node (жодних залежностей) і нічим не привʼязаний
до конкретного хостингу. Потрібен лише Node 18 або новіший.

## Запуск

```bash
node server/set-password.mjs    # один раз: задати пароль до адмінки
node server/index.mjs           # сайт і адмінка на http://localhost:4199
```

| Адреса | Що це |
|---|---|
| `/` | Сайт |
| `/blog` | Блог |
| `/admin` | Панель керування |
| `/api/public/rates` | Курси у JSON — звідси їх читає відкрита сторінка |

Завантажені з адмінки зображення лягають у теку `images/` поруч із рештою
графіки сайту.

## Змінні середовища

| Змінна | Призначення |
|---|---|
| `PORT` | Порт (типово 4199) |
| `DATA_DIR` | Тека з даними. **Винесіть її за межі репозиторію** — тоді деплой не затре курси, які щойно зберіг клієнт. Наприклад `/var/lib/bestobmin` |
| `SECURE_COOKIES=1` | Вмикайте, коли сайт працює по HTTPS: кука сесії стає `Secure`, додається HSTS |
| `TRUST_PROXY=1` | Вмикайте за nginx/Caddy, щоб у журнал потрапляв реальний IP, а не адреса проксі |
| `ADMIN_PASSWORD_SALT`, `ADMIN_PASSWORD_HASH` | Альтернатива файлу `auth.json`: тримати хеш пароля у змінних середовища |

## За зворотним проксі

Сервер навмисно не вміє HTTPS — цим має займатися nginx або Caddy.

```nginx
server {
  server_name bestobmin.com.ua;
  location / {
    proxy_pass http://127.0.0.1:4199;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  }
}
```

Запускайте процес через systemd, щоб він піднімався після перезавантаження:

```ini
[Unit]
Description=BEST site
After=network.target

[Service]
WorkingDirectory=/srv/bestobmin
ExecStart=/usr/bin/node server/index.mjs
Environment=SECURE_COOKIES=1 TRUST_PROXY=1 DATA_DIR=/var/lib/bestobmin
Restart=always
User=www-data

[Install]
WantedBy=multi-user.target
```

## Що де зберігається

| Файл | Вміст | У git |
|---|---|---|
| `data/rates.json` | Курси валют | так (як початкові дані) |
| `data/branches.json` | Відділення | так |
| `data/texts.json` | Тексти секцій | так |
| `content/posts/*.md` | Статті блогу | так |
| `data/auth.json` | Хеш пароля, права 600 | **ні** |
| `data/.sessions.json` | Активні сесії | **ні** |
| `data/.backups/` | 30 попередніх версій кожного файлу | **ні** |
| `data/auth.json.prev` | Попередній хеш пароля | **ні** |
| `data/.known-ips.json` | Адреси, з яких уже входили | **ні** |
| `data/audit.log` | Хто і коли що змінював | **ні** |

Відкотити помилкову правку можна вручну: скопіювати потрібний файл з
`data/.backups/` на місце і перезапустити збірку (`node assemble.mjs`).

## Як зміни потрапляють на сайт

**Курси — миттєво.** Сторінка щодві хвилини (і щоразу, коли вкладка знову
стає активною) питає `/api/public/rates`. Перезбірка не потрібна: курси
оновлюються навіть на вкладці, яку відвідувач відкрив годину тому. Якщо API
недоступний, залишаються ті курси, що вшиті у сторінку під час збірки.

**Новини, відділення, тексти — за хвилину.** Після збереження сервер сам
запускає `node assemble.mjs` і перегенеровує статичні сторінки.

## Безпека

Що зроблено:

- **Пароль** ніде не зберігається — лише scrypt-хеш із випадковою сіллю
  (N=16384). Звірка constant-time.
- **Сесія** — 256-бітний випадковий токен у куці `HttpOnly; SameSite=Strict`
  (і `Secure` при `SECURE_COOKIES=1`). 12 годин бездіяльності або 7 діб
  загалом — і сесія завершується.
- **CSRF** — будь-яка зміна даних вимагає заголовка `X-CSRF-Token`, який
  збігається з токеном сесії; плюс перевірка `Origin`.
- **Підбір пароля** — експоненційна затримка після 8 невдалих спроб з однієї
  адреси, до 15 хвилин. Відповідь на невірний пароль завжди однакова за часом.
- **Валідація** — усе, що приходить від браузера, збирається наново поле за
  полем. В адмінці можна рухати лише числа: назви валют, підписи й прапори
  беруться з сервера, тож підміна тіла запиту нічого не дає.
- **Доступ до файлів** — шлях нормалізується й перевіряється, що він
  всередині проєкту; теки `data/`, `server/`, `content/`, `parts/` і все, що
  починається з крапки, не віддаються взагалі.
- **Заголовки** — CSP для адмінки, `X-Frame-Options: DENY`,
  `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `Permissions-Policy`,
  HSTS під HTTPS.
- **Запис на диск** — через тимчасовий файл і `rename`, тож обрив не лишить
  половини файлу. Попередня версія зберігається.
- **Завантаження зображень** — тип визначається за першими байтами файлу, а
  не за назвою чи заявленим Content-Type: `.webp`, усередині якого PHP, не
  пройде. Приймаються лише JPG, PNG і WebP; SVG — ні, бо може нести скрипт.
  Назву файлу складає сервер (слаг + хеш вмісту), тому `../` у назві нічого
  не дає. Стеля — 8 МБ на файл, але браузер і так зменшує фото до 1600 px і
  перекодовує у WebP перед відправкою.

### Проти покладання сайту

- **Обмеження частоти** на кожну адресу, окремими відрами: статика 600/хв,
  API 120/хв, публічні курси 240/хв, вхід 10/хв, завантаження 20/хв. Межі
  підібрані так, щоб звичайна робота їх не відчувала: сторінка відвідувача
  питає курси раз на дві хвилини, касир зберігає кілька разів на годину.
- **Курси віддаються з памʼяті**, не з диска, і з ETag — повторний запит
  зазвичай отримує 304 без тіла. Шквал запитів не породжує дискових
  читань.
- **Таймаути сокетів** (заголовки 10 с, запит 30 с, keep-alive 5 с, не
  більше 512 зʼєднань) — проти повільних зʼєднань, що займають слоти й
  нічого не надсилають.
- **Процес не падає від однієї помилки**: необроблений виняток пишеться в
  журнал, сервер продовжує працювати.

### Проти підміни курсу

Це найцінніша для зловмисника дія: курси доходять до відвідувачів за
секунди й не потребують перезбірки. Тому:

- Зміна курсу більш ніж на **15 %** (або 5 відсоткових пунктів для
  спреду) не зберігається — сервер повертає перелік того, що зрушило, і
  чекає окремого підтвердження. Те саме ловить і звичайну описку касира.
- Кожна відхилена спроба лягає в журнал як загроза.
- Назви валют, підписи й прапори беруться з сервера: навіть повністю
  підроблений запит може рухати лише числа.

### Проти відбирання доступу

- **Сесія привʼязана до браузера**: кука, скопійована й відтворена з
  іншого клієнта, не приймається.
- **Підбір пароля з однієї адреси** — експоненційна затримка після
  8 спроб. **З багатьох адрес** — після 40 невдач за 15 хвилин вхід
  закривається для всіх *крім адрес, з яких уже був успішний вхід*. Це
  важливо: інакше ботнет міг би просто замкнути вас самих.
- Попередній хеш пароля зберігається як `auth.json.prev`, тож помилкова
  зміна відновлюється.
- Розділ **«Журнал»** в адмінці показує входи, невдалі спроби й відхилені
  зміни курсу, і сам попереджає, якщо їх забагато.

### Чого цей сервер не вміє — і що треба додати зовні

**Обʼємну DDoS-атаку жоден Node-процес не витримає.** Якщо нішу справді
атакують, поставте перед сайтом Cloudflare (безкоштовного тарифу
достатньо):

1. Домен на Cloudflare, проксі (помаранчева хмарка) увімкнений.
2. На `/admin` і `/api/*` — правило WAF: дозволити лише з ваших IP, або
   поставити перевірку (Managed Challenge). Адмінка не потрібна нікому
   з інтернету.
3. Увімкнути «Under Attack Mode» на випадок напливу.
4. Приховати справжню адресу сервера: приймати зʼєднання лише з
   діапазонів Cloudflare (`ufw allow from <cf-range>`), інакше атакувати
   можна в обхід.

Додатково варто:

- **Резервні копії поза сервером.** `data/` і `content/` — це весь вміст
  сайту. Щоденний `rsync` чи `restic` в інше місце рятує і від зламу, і
  від збою диска.
- **Fail2ban** на SSH, вхід по ключу, пароль вимкнений.
- **Моніторинг доступності** (UptimeRobot або подібний) — щоб ви дізнались
  про падіння першими, а не від клієнтів.

### Чого немає

Окремих облікових записів з ролями, двофакторної автентифікації,
відновлення пароля поштою. Для команди з кількох людей це варто додати;
зараз пароль міняється командою `node server/set-password.mjs` на сервері.

## Якщо забули пароль

```bash
node server/set-password.mjs    # просто задайте новий
```

Старі сесії лишаються активними — щоб обірвати всі, видаліть
`data/.sessions.json` і перезапустіть сервер.
